# Blender storytelling and visual grammar

Use one recurring motif whose transformations earn the end reveal. Make each major beat convey a clear idea. Contrast quiet, playful and energetic moments; do not require perpetual camera motion. Combine typography, geometry, sound and movement in a single cohesive world.

Deliver BRIEF.md, STORYBOARD.md and a validated project.json. Each scene specifies id, inclusive frame range, exact on-screen copy, colors, 3D objects, camera path, entry/exit transformation, related musical and SFX events, meaning and pass/fail standards. All handoffs declare source/target projected x/y anchor and intentional continuity mode. Verify the proposed visual metaphor is geometrically and linguistically possible.

Reject a text-card slideshow, random 3D props, unsupported marketing claims, mismatched identity colors and end cards that look disconnected from the film.
## Non-negotiable operation rules

- Use the approved project brief and declarative frame/event specification; never invent missing institutional facts, copy or licenses.
- Produce native Blender bpy objects and editable .blend scene data, not a browser animation mislabeled as Blender.
- Verify using actual tests, rendered frames, reproducible commands and output paths.
- Technical PASS is distinct from aesthetic or listening HUMAN_REVIEW_REQUIRED.
- If required assets or executable APIs are unavailable, report BLOCKED; never silently substitute.
